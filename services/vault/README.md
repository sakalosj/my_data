# vault

HashiCorp Vault server: raft storage in the `vault-data` docker volume, and TLS with
a self-signed cert generated by `svc`. Listens on port 8200.

- [compose.yaml](compose.yaml), [config/vault.hcl](config/vault.hcl), [.env.example](.env.example)
- `secrets/<host>/tls/vault.{crt,key}`: TLS cert (gitignored)
- `secrets/<host>/init.json`: **unseal keys + root token** (gitignored, mode 600).
  This is the only copy, so back it up somewhere safe, e.g. a password manager.

Requirements on this machine: `brew install vault jq`. The host name must resolve
(e.g. `/etc/hosts`: `172.24.97.70 jsakalos-dev`).

## 1. Parameters

Paste first in every shell; all blocks below use these:

```sh
export VAULT_HOST=jsakalos-dev        # name used for -H, cert and VAULT_ADDR (keep it stable)
export VAULT_IP=172.24.97.70          # extra cert SAN, so https://<ip>:8200 also verifies
export SVC_SSH_USER=root              # ssh user for svc (host only accepts root key)
export VAULT_SECRETS=$HOME/my_data/services/vault/secrets/$VAULT_HOST
export VAULT_ADDR=https://$VAULT_HOST:8200
export VAULT_CACERT=$VAULT_SECRETS/tls/vault.crt
```

## 2. Deploy + init + login (new host)

```sh
svc vault certs  -H $VAULT_HOST --san $VAULT_IP   # self-signed cert for name + IP
svc vault deploy -H $VAULT_HOST                   # rsync to ~/services/vault, pull, up -d
svc vault init   -H $VAULT_HOST                   # prints + saves keys/token to $VAULT_SECRETS/init.json ONCE
svc vault unseal -H $VAULT_HOST
vault status
vault login -no-print "$(jq -r .root_token $VAULT_SECRETS/init.json)"
vault secrets enable -path=secret kv-v2           # key/value store at secret/
vault token lookup
```

It's safe to paste again: `certs` and `init` refuse to overwrite existing output, and
`deploy` only restarts what changed.

## 3. Daily use (new shell / after restart)

Paste section 1, then:

```sh
svc vault status -H $VAULT_HOST | grep -E 'Initialized|Sealed'
svc vault unseal -H $VAULT_HOST                   # needed after every container / host restart
vault login -no-print "$(jq -r .root_token $VAULT_SECRETS/init.json)"
vault kv list secret/
```

`vault login` stores the token in `~/.vault-token`, so it's only needed once per token.

## 4. Store and read secrets

```sh
# set a secret field from a hidden prompt: type it, press Enter (the newline is NOT stored).
# vset (dotfiles/common/.aliases) creates the secret, or patches it if it exists (other fields kept).
vset secret/myapp password username=admin         # extra key=value args are stored as-is
vset secret/myapp api_key                         # add/change one more field

# non-secret fields directly (each write creates a new version)
vault kv patch secret/myapp username=admin2

# get
vault kv get secret/myapp                         # all fields
vault kv get -field=password secret/myapp         # one value, for scripts
vault kv get -format=json secret/myapp | jq .data.data
vault kv list secret/
vault kv get -version=1 secret/myapp              # older version

# delete
vault kv delete secret/myapp                      # soft delete latest version
vault kv metadata delete secret/myapp             # all versions, permanent
```

Don't use plain `vault kv put ... password=-` interactively: it reads stdin until EOF, so
you must press Enter + Ctrl-D and the Enter ends up stored as a trailing newline. Check
a value for it with `vault kv get -field=password secret/myapp | od -c | tail -2`
(a `\n` at the end means re-set it with `vset`).

## 5. Without the vault CLI (HTTP API with curl)

Any machine with `curl` and `jq` works. It needs the CA cert (`vault.crt`, safe to copy)
and a token. Prefer a personal token (section 8) over the root token on other machines.

```sh
# on another machine: copy the cert once, then set VAULT_TOKEN instead of reading init.json
# scp ~/my_data/services/vault/secrets/jsakalos-dev/tls/vault.crt other:~/.vault-ca.crt
# export VAULT_ADDR=https://jsakalos-dev:8200 VAULT_CACERT=~/.vault-ca.crt
# read -rs 'VAULT_TOKEN?token: ' && export VAULT_TOKEN && echo

export VAULT_TOKEN=$(jq -r .root_token $VAULT_SECRETS/init.json)
# token passed via a file descriptor, so it doesn't show in `ps`
vapi() { curl -sS --cacert "$VAULT_CACERT" -H @<(printf 'X-Vault-Token: %s\n' "$VAULT_TOKEN") "$@"; }

vapi "$VAULT_ADDR/v1/secret/data/myapp" | jq .data.data               # all fields
vapi "$VAULT_ADDR/v1/secret/data/myapp" | jq -r .data.data.password    # one value
vapi "$VAULT_ADDR/v1/secret/data/myapp?version=1" | jq .data.data     # older version
vapi -X LIST "$VAULT_ADDR/v1/secret/metadata/" | jq -r '.data.keys[]'  # list

# write (replaces all fields, new version); password via env + stdin, not argv
read -rs 'pw?password: ' && echo
pw="$pw" jq -n '{data: {username: "admin", password: env.pw}}' \
  | vapi -X POST --data-binary @- "$VAULT_ADDR/v1/secret/data/myapp" | jq .data.version
unset pw

# delete all versions
vapi -X DELETE "$VAULT_ADDR/v1/secret/metadata/myapp" -o /dev/null -w '%{http_code}\n'   # 204 = ok
```

The API path is `secret/data/<name>` for values and `secret/metadata/<name>` for list/delete
(the CLI's `secret/<name>` maps to these). Errors come back as `{"errors":[...]}`:
an empty list means not found, and `permission denied` means a bad or expired token.
The macOS system curl doesn't support `--fail-with-body`, so check the JSON for errors.

## 6. Web UI

```sh
open "$VAULT_CACERT"                              # Keychain Access -> Trust: Always Trust (removes browser warning)
jq -r .root_token $VAULT_SECRETS/init.json | pbcopy
open "$VAULT_ADDR/ui"                             # Method: Token, paste
```

## 7. Renew or change the TLS cert (e.g. host renamed)

`deploy` syncs the new cert and reloads it into the running Vault, which stays unsealed:

```sh
svc vault certs  -H $VAULT_HOST --san $VAULT_IP --force
svc vault deploy -H $VAULT_HOST --no-pull
openssl s_client -connect $VAULT_HOST:8200 </dev/null 2>/dev/null | openssl x509 -noout -ext subjectAltName -enddate
vault status
```

If `VAULT_HOST` changed, move the old secrets dir first, so `init.json` matches the new name:
`mv $HOME/my_data/services/vault/secrets/<old> $VAULT_SECRETS`.
If you trusted the old cert in Keychain, trust the new one too.

## 8. Personal token instead of root (optional)

```sh
vault policy write personal - <<'EOF'
path "secret/data/*"     { capabilities = ["create", "read", "update", "patch", "delete", "list"] }
path "secret/metadata/*" { capabilities = ["read", "list", "delete"] }
path "secret/delete/*"   { capabilities = ["update"] }
path "secret/undelete/*" { capabilities = ["update"] }
EOF
vault login -no-print "$(vault token create -policy=personal -ttl=720h -display-name=personal -field=token)"
vault token lookup
```

## 9. Backup (raft snapshot, needs root token)

```sh
vault login -no-print "$(jq -r .root_token $VAULT_SECRETS/init.json)"
vault operator raft snapshot save $VAULT_SECRETS/vault-$(date +%F).snap
# restore: vault operator raft snapshot restore -force $VAULT_SECRETS/vault-YYYY-MM-DD.snap
```

A snapshot can only be unsealed with its own Vault's unseal keys, so keep it next to `init.json`.

## Local test instance

```sh
cd ~/my_data/services
export VAULT_PORT=18200
svc vault certs && svc vault up && svc vault init && svc vault unseal && svc vault status
curl -s --cacert vault/secrets/local/tls/vault.crt https://127.0.0.1:18200/v1/sys/health | jq

# cleanup
yes | svc vault down -v && rm -r vault/secrets/local && unset VAULT_PORT
```

## Troubleshooting

| Symptom | Fix |
|---|---|
| `x509: certificate is valid for localhost, not <host>` | The cert has no SAN for that name, or the container still serves an old cert: section 7 |
| `Vault is sealed` / `Sealed true` | `svc vault unseal -H $VAULT_HOST` |
| `Permission denied (publickey)` on deploy | wrong ssh user: `export SVC_SSH_USER=root`, `-u root` or `~/.ssh/config` |
| `no TLS cert in services/vault/secrets/<h>/tls` | `svc vault certs -H $VAULT_HOST` (the name must match `-H` exactly) |
| `no handler for route "secret/..."` | `vault secrets enable -path=secret kv-v2` |
| `vault kv put ... password=-` hangs, or the value has a trailing newline | use `vset secret/<name> password` (section 4) |
| `permission denied` from vault CLI | not logged in or token expired: `vault login` (section 3) |
| `init.json exists; vault already initialized?` | already initialized; to start over: `svc vault down -H $VAULT_HOST -v`, then move the old `init.json` away |
